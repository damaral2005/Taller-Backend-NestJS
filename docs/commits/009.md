# Overview del incremento 009 — documentación OpenAPI con Swagger

Fecha: 2026-10-12. Mensaje: `feat: add OpenAPI documentation with Swagger UI`.
Rama: `feature-swagger`, desde `2a86b32` (merge de catálogo, movimientos y retiro del 2FA en main). El usuario aprobó el incremento y las opciones recomendadas: Swagger siempre activo, decoradores explícitos y esquemas de respuesta.
Estado: implementación y verificaciones locales completas; commit local. Push y CI quedan sujetos a autorización.

## Resultado

- `GET /api/v1/docs` sirve Swagger UI y `GET /api/v1/docs-json` el documento OpenAPI 3.0. Ambas rutas son públicas y están activas en todos los entornos. Los recursos de la UI se sirven desde la API, sin CDN.
- Las 14 operaciones existentes están documentadas:
  - agrupadas por módulo, con un resumen que indica el rol permitido;
  - con parámetros de ruta y query, y cuerpos con los mismos patrones, longitudes, enumeraciones y rangos que class-validator;
  - con sus respuestas de éxito y error.
- Las 12 rutas protegidas declaran el esquema bearer JWT; con **Authorize** se prueban desde el navegador. Las seis rutas de solo admin documentan `403`.
- Esquemas de respuesta para producto, usuario seguro, movimiento, identidad, login, páginas y error común. Coinciden campo a campo con las proyecciones existentes y no contienen contraseñas, hashes, claves de seed ni datos de sesión.
- No cambia ningún contrato, guard, validación, regla de negocio ni esquema de BD. Las proyecciones `*.view.ts` siguen iguales. Solo se añadieron `USER_ROLES`, `MOVEMENT_TYPES` y `USERNAME_PATTERN` para que validación y documentación usen la misma fuente.

## SDD y documentación

Spec, plan y tareas de 009 escritos antes del código, con criterios S-01 a S-07 y decisiones D-47 a D-50. Durante la implementación, la prueba S-02 detectó que el conteo inicial (15) era incorrecto: hay 14 operaciones. Spec y prueba se corrigieron a 14.

## Verificación local

Contenedor Linux limpio con Node 24.21.0, npm 11.17.0 y PostgreSQL 16 real (base `inventory_test`), instalado con `npm ci` desde el lockfile.

- Formato, lint, tipos y build pasan.
- `npm run test:cov`: **450 pruebas en 18 suites**, de las cuales 439 son regresiones y 11 son casos nuevos en `test/swagger.e2e-spec.ts`. Cobertura sobre **54 archivos fuente**:

  | Métrica    | Cobertura |
  | ---------- | --------- |
  | Sentencias | 98,51%    |
  | Ramas      | 94,39%    |
  | Funciones  | 99,11%    |
  | Líneas     | 98,91%    |

  Los seis archivos nuevos tienen 100%. En el mismo entorno, la versión anterior medía 94,33% de ramas: los decoradores no reducen la cobertura. Las cifras de 008 (96,18% de ramas) se midieron en Windows y no son comparables directamente.

- La prueba e2e verifica:
  - UI y JSON;
  - la lista exacta de operaciones;
  - seguridad y respuestas `401/403/404/409/429`;
  - obligatorios, patrones y rangos de los DTOs;
  - campos de respuesta sin secretos;
  - que los campos extra siguen dando `400` y las rutas protegidas siguen dando `401`.
- Smoke del proceso compilado con `NODE_ENV=production` en un esquema descartable:
  - se aplicaron migración y seed;
  - `/docs`, sus recursos y `/docs-json` responden `200`;
  - login de admin → JWT → `GET /products` responde `200`, y sin JWT responde `401`.

  El proceso se cerró y el esquema se eliminó.

- Dependencias: solo `@nestjs/swagger` 12.0.2, con versión exacta. Sus dependencias transitivas son `swagger-ui-dist`, `js-yaml`, `@nestjs/mapped-types`, `@microsoft/tsdoc` y `@scarf/scarf`. El script postinstall de telemetría de `@scarf/scarf` no se ejecuta con la política de scripts de npm 11.

## Límites y siguiente incremento

- La documentación es pública también en producción (D-48). Si el grupo prefiere ocultarla, basta con condicionar `setupSwagger` a una variable de entorno.
- Los ejemplos del documento son ilustrativos y no contienen credenciales.
- Swagger no reemplaza la colección Postman (R-06) ni el informe (R-07). El JSON sirve como punto de partida para ambos.
- Pendientes: Postman, informe final, despliegue y revisión del grupo antes de integrar en main.
