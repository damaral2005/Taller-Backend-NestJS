## Qué cambia y por qué

El grupo decidió que el segundo factor (TOTP) no debía existir. Este incremento es una corrección de alcance: el único mecanismo de autenticación es usuario y contraseña que producen un JWT.

- `POST /auth/login` recibe `{username, password}` y devuelve `{accessToken, tokenType, expiresIn}` (15 minutos). El token sigue ligado a una sesión persistida, por lo que `logout` lo revoca (D-38).
- Se mantienen el bloqueo de cuenta (5 fallos → 15 minutos) y el límite por IP (20/min); el error de credenciales es uniforme (`401`).
- Rutas retiradas (ahora `404`): `/auth/2fa/setup`, `/auth/2fa/confirm` y `/auth/verify-2fa`.
- `POST /users` devuelve directamente el usuario seguro, sin credencial de enrolamiento; el nuevo usuario inicia sesión de inmediato. La regla de «último admin» queda en «no degradar al último administrador registrado» (D-39).
- Se eliminan `enroll.ts`, `enrollment.ts`, la entidad `auth-proof`, el script `auth:enroll`, el cifrado AES-GCM, la dependencia `otpauth` y la variable `TOTP_ENCRYPTION_KEY` (si un `.env` antiguo la conserva, se ignora).
- Migración `1791244802000-remove-two-factor`: elimina `auth_proofs` y las cuatro columnas TOTP de `users`. **Destructiva**: los secretos TOTP existentes se pierden; `down()` solo restaura la estructura vacía (D-40).
